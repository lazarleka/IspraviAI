# Entities

> The contract between `frontend/` and `beckend/`: fields with types, relations, access rules, routes,
> status codes and error codes. This file exists twice, `docs/entities.md` (repo root) and
> `beckend/docs/entities.md`; they must stay identical: change both in the same commit.
> Backend code: `beckend/app/<domain>/`. Frontend code: `frontend/src/features/<name>/types.ts` and
> `frontend/src/features/<name>/api/<name>-api.ts`. Product rules are in `SPEC.md`.

## Conventions

- Base path: `/api` (the frontend calls `/api/...`; in development Vite proxies it to port 8000)
- JSON keys are camelCase (`wrongIndex`, `createdAt`), in requests and responses
- Ids are integers assigned by the backend
- Dates are ISO 8601 strings in UTC (`2026-11-05T09:30:00Z`), assigned by the backend
- Auth: `POST /api/auth/register` or `POST /api/auth/login` return a token; protected routes take
  `Authorization: Bearer <token>`. Every route below needs a token unless it says "no".
- `POST` answers `201` with the created record, `DELETE` answers `204` with no body
- `GET` lists are paginated: `?page=1&size=50` (size ≤ 500) answers `{"total", "items", "pages"}`, newest first
- Every error has one shape: `{"detail": "...", "code": "snake_case_code"}` plus `fieldErrors` when a field
  is at fault; 401 responses also carry `WWW-Authenticate: Bearer`

| Status | When | Example body |
| --- | --- | --- |
| 401 | missing token / invalid token / wrong password | `{"detail": "Authentication required", "code": "not_authenticated"}` / `"invalid_token"` / `"invalid_credentials"` |
| 403 | signed in, but not allowed | `{"detail": "Only the owner can use this deck", "code": "not_deck_owner"}` |
| 404 | record does not exist | `{"detail": "Deck not found", "code": "deck_not_found"}` |
| 409 | conflicts with existing data or state | `{"detail": "Username is already taken", "code": "username_taken", "fieldErrors": {"username": "Username is already taken"}}` |
| 413 / 415 | uploaded file too large / wrong type | `{"detail": "File is larger than 10 MB", "code": "file_too_large"}` / `"unsupported_file_type"` |
| 422 | invalid input | `{"detail": "Validation failed", "code": "validation_error", "fieldErrors": {"topic": "String should have at least 3 characters"}}` |

## User

Code: `app/users/`; register/login/me in `app/auth/`.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| id | number | yes | assigned by the backend |
| email | string, valid email | yes | unique, stored lowercase; returned only by `/auth/*` |
| username | string, 3–20 characters, `a-z`, `0-9`, `_` | yes | unique, stored lowercase; used to find friends |
| displayName | string, 1–60 characters | yes | |
| createdAt | date | yes | assigned by the backend |

The password (8–72 characters) is sent only on register and login; it is never returned.
`PublicUser` = `{id, username, displayName}` is what other users see.

| Route | Auth | Body | Response |
| --- | --- | --- | --- |
| `POST /api/auth/register` | no | `{email, password, displayName, username}` | `201 {token, user}`, `409 email_already_registered`, `409 username_taken`, `422` |
| `POST /api/auth/login` | no | `{email, password}` | `200 {token, user}`, `401 invalid_credentials` |
| `GET /api/auth/me` | yes | | `200` user |
| `GET /api/users?search=&page=&size=` | yes | | `200 Page[PublicUser]`; `search` (≥ 2 characters) matches the start of the username; excludes yourself |

## Deck

Code: `app/decks/` (`models/deck.py`). A set of cards generated by the AI from a topic or an uploaded file.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| id | number | yes | |
| title | string, 3–80 characters | yes | from the request, or generated from the topic / file name |
| subject | `biology` \| `history` \| `programming` \| `math` \| `physics` \| `chemistry` \| `language` \| `other` | yes | picks the deck's color in the UI; guessed by the AI when not sent |
| sourceType | `topic` \| `file` | yes | |
| topic | string, 3–200 characters, or `null` | when `sourceType = topic` | |
| fileName | string or `null` | when `sourceType = file` | the uploaded file's name |
| kind | `study` \| `match` | yes | `match` decks belong to a PvP match and are not listed on the home screen |
| status | `generating` \| `ready` \| `failed` | yes | assigned by the backend |
| requestedCards | 5–20 | yes | |
| cardCount | number | yes | cards that passed validation; assigned by the backend |
| progress | number 0–100 | yes | % of cards in box ≥ 3 for the signed-in user; computed |
| dueCount | number | yes | cards due now for the signed-in user; computed |
| ownerId | number | yes | the signed-in user who created it; assigned by the backend |
| createdAt | date | yes | |

**Relations:** a deck belongs to one user (`ownerId`) and has many cards. Deleting a user deletes their
decks; deleting a deck deletes its cards and progress.

**Access rules:** only the owner can see, study or delete a `study` deck. A `match` deck is read only
through its match, by its two players, after the match ended.

| Route | Auth | Body | Response |
| --- | --- | --- | --- |
| `GET /api/decks?page=&size=` | yes | | `200 Page[Deck]`, only your `study` decks, newest first |
| `POST /api/decks` | yes | `{topic, title?, subject?, requestedCards}` | `201` deck with `status: "generating"`, `422` |
| `POST /api/decks/upload` | yes | `multipart/form-data`: `file` (PDF, TXT, MD, ≤ 10 MB), `title?`, `subject?`, `requestedCards` | `201` deck with `status: "generating"`, `413 file_too_large`, `415 unsupported_file_type`, `422` |
| `GET /api/decks/:id` | owner | | `200` deck (poll every 2 s while `generating`), `403 not_deck_owner`, `404 deck_not_found` |
| `DELETE /api/decks/:id` | owner | | `204`, `403`, `404` |

## Card

Code: `app/decks/` (`models/card.py`). One sentence or code fragment, split into segments, with exactly
one wrong segment (or none).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| id | number | yes | |
| deckId | number | yes | |
| kind | `text` \| `code` | yes | |
| language | string or `null` | when `kind = code` | `c`, `cpp`, `python`, `java`, `javascript`, `sql`, ... |
| segments | string[], 2–8 items, each 1–200 characters | yes | what the user taps |
| factKey | string | yes | groups the variants of the same fact |
| wrongIndex | number or `null` | **only after answering** | index into `segments`; `null` = the card has no error |
| correctText | string or `null` | **only after answering** | what the wrong segment should say |
| explanation | string, ≤ 300 characters | **only after answering** | |
| errorType | `fact` \| `calculation` \| `logic` \| `fake_source` \| `exaggeration` \| `code_bug` \| `null` | **only after answering** | |
| sourceRef | string or `null` | **only after answering** | e.g. `str. 12` |

`CardQuestion` = `{id, deckId, kind, language, segments}` is what the client gets before answering.
`CardAnswer` = `CardQuestion` + `{wrongIndex, correctText, explanation, errorType, sourceRef}`.
The backend never sends the answer fields before the user answered the card (or the match card ended).

## Study (progress and reviews)

Code: `app/study/`. Progress of one user on one card (Leitner box).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| cardId | number | yes | unique together with the user |
| box | 1–4 | yes | starts at 1 |
| dueAt | date | yes | box 1 = now, 2 = +3 days, 3 = +7 days, 4 = +14 days |
| correctCount, wrongCount | number ≥ 0 | yes | |
| lastSeenAt | date or `null` | yes | picks the variant seen least recently |
| reported | boolean | yes | a reported card is not shown to this user again |

| Route | Auth | Body | Response |
| --- | --- | --- | --- |
| `GET /api/study/today` | yes | | `200 {dueCount, decks: [{deckId, title, subject, dueCount}]}` |
| `GET /api/study/decks/:deckId/next?size=10` | owner | | `200 {items: CardQuestion[]}`: due cards first, then new ones, one variant per fact; `403`, `404`, `409 deck_not_ready` |
| `POST /api/study/cards/:cardId/answer` | owner | `{selectedIndex: number \| null, attempt: 1 \| 2}` (`null` = "Nema greške") | `200 {correct, points, card: CardAnswer \| null}`; `card` is set when `correct` or `attempt = 2`; `403`, `404`, `422` |
| `POST /api/study/cards/:cardId/report` | owner | `{reason?: string ≤ 200}` | `204`, `403`, `404` |

Points: correct on attempt 1 = 10 (box + 1), on attempt 2 = 5 (same box), wrong on attempt 2 = 0 (box 1).

## Friendship

Code: `app/friends/`. One row per pair of users, stored as `userLowId < userHighId` with a unique pair,
so the same two people can never have two rows.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| id | number | yes | |
| requestedById | number | yes | who sent the request; assigned by the backend |
| status | `pending` \| `accepted` | yes | a declined or removed friendship is deleted |
| friend | PublicUser | yes | the other person, computed for the signed-in user |
| online | boolean | yes | the friend has an open WebSocket; computed |
| createdAt | date | yes | |
| acceptedAt | date or `null` | yes | |

**Access rules:** only the two users of a friendship see it. Only the receiver accepts; either user can
decline or cancel (pending) or remove (accepted).

| Route | Auth | Body | Response |
| --- | --- | --- | --- |
| `GET /api/friends?page=&size=` | yes | | `200 Page[Friendship]`, accepted only |
| `GET /api/friends/requests` | yes | | `200 {incoming: Friendship[], outgoing: Friendship[]}` |
| `POST /api/friends/requests` | yes | `{username}` | `201` friendship (`pending`), `404 user_not_found`, `409 already_friends`, `409 request_already_sent`, `422 cannot_befriend_yourself` |
| `POST /api/friends/requests/:id/accept` | receiver | | `200` friendship (`accepted`), `403 not_request_receiver`, `404 friendship_not_found` |
| `DELETE /api/friends/:id` | either user | | `204` (decline, cancel or remove), `404 friendship_not_found` |

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| id | number | yes | |
| challenger | PublicUser | yes | the signed-in user who sent it; assigned by the backend |
| opponent | PublicUser | yes | must be an accepted friend |
| topic | string, 3–200 characters | yes | |
| cardCount | 5 \| 10 \| 15 | yes | default 10 |
| status | `pending` \| `accepted` \| `declined` \| `expired` \| `cancelled` | yes | |
| deckStatus | `generating` \| `ready` \| `failed` | yes | the match deck is generated as soon as the challenge is created |
| matchId | number or `null` | yes | set when accepted |
| expiresAt | date | yes | `createdAt + 2 minutes` |
| createdAt | date | yes | |

| Route | Auth | Body | Response |
| --- | --- | --- | --- |
| `POST /api/challenges` | yes | `{opponentId, topic, cardCount}` | `201` challenge, `403 not_friends`, `409 challenge_already_pending`, `422` |
| `GET /api/challenges/pending` | yes | | `200 {incoming: Challenge[], outgoing: Challenge[]}` (not expired) |
| `POST /api/challenges/:id/accept` | opponent | | `200` challenge with `matchId`, `403 not_challenge_opponent`, `404 challenge_not_found`, `409 challenge_expired`, `409 deck_generation_failed` |

## Match

Code: `app/matches/` (`models/match.py`, `models/match_answer.py`, `engine/`).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| id | number | yes | |
| challengeId | number | yes | unique: one match per challenge |
| deckId | number | yes | the `match` deck |

## Realtime (WebSocket)

One connection per signed-in user: `GET /api/ws` (upgrade). It carries presence, challenge invites and
the live match. Messages are JSON `{"type": "...", ...}` with camelCase keys.

- The first client message must be `{"type": "auth", "token": "<jwt>"}` within 5 s; otherwise the server
  closes with code `4401`. The token is never put in the URL.
- The server is authoritative: it runs the timer, decides who answered first by its own receive time, and
  sends `CardAnswer` fields only in `card_end`.

**Client → server**

| type | Fields | When |
| --- | --- | --- |
| `auth` | `token` | first message |
| `match_join` | `matchId` | on opening `/match/:id` (also to rejoin after a disconnect) |
| `match_tap` | `matchId`, `cardId`, `selectedIndex` (number or `null`) | tapped a segment; `null` = "Nema greške" (the card has no error) |
| `match_dont_know` | `matchId`, `cardId` | clicked "Ne znam" |
| `ping` | | every 20 s |

**Server → client**

| type | Fields | When |
| --- | --- | --- |
| `auth_ok` | `userId` | after `auth` |
| `presence` | `userId`, `online` | a friend connected or disconnected |
| `challenge_received` | `challenge` | someone challenged you |
| `challenge_updated` | `challenge` | accepted, declined, expired, cancelled, or `deckStatus` changed |
| `match_ready` | `matchId`, `startsAt` | both players joined; 3-2-1 countdown until `startsAt` |
| `card_start` | `matchId`, `index`, `total`, `card: CardQuestion`, `endsAt` | a new card (20 s) |
| `answer_result` | `matchId`, `cardId`, `correct`, `points` | reply to your own `match_tap` |
| `opponent_action` | `matchId`, `cardId`, `action: "wrong" \| "dont_know"` | the opponent is done with the card |
| `card_end` | `matchId`, `cardId`, `winnerId \| null`, `reason: "correct" \| "both_done" \| "timeout"`, `card: CardAnswer`, `scores: {[userId]: number}` | the card is over; next card after 3 s |
| `opponent_disconnected` | `matchId`, `graceSeconds` | the opponent dropped; 15 s to come back |
| `match_end` | `matchId`, `winnerId \| null`, `status`, `scores` | the match is over |
| `error` | `code`, `detail` | e.g. `not_match_player`, `card_already_ended`, `already_answered` |
| `pong` | | reply to `ping` |
